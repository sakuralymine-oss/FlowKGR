# Inductive 失败改动与已确认结论

更新时间：2026-08-11

## 记录原则

- 只记录已经实际运行、且结果不足以支持继续采用的改动。
- `H@10@50` 只表示 50 个采样负例协议下的指标，不能当作全实体 `H@10`。
- 验证集、测试集和不同数据版本不能相互替代。
- 没有完成正式对照实验的想法，不写成“已经失败”。

## 1. 参考基线与当前主要现象

当前统一主链为：

`PPR候选子图 -> 查询条件GNN -> 候选级VAE -> 条件Score Flow Matching -> Ranking`

已经观察到的典型结果：

| 数据 | MRR | H@10 | PPR答案召回 | 主要现象 |
|---|---:|---:|---:|---|
| WN18RR-v1 | 0.7153 | 0.8137 | 0.8646 | MRR接近对比方法，H@10仍有差距 |
| WN18RR-v4 | 0.6564 | 0.7255 | 0.8493 | MRR接近DiffusionE，H@10偏低 |
| FB15k-237-v1（早期） | 0.2945 | 0.3796 | 0.6435 | 候选召回和内部排序同时不足 |
| NELL-v2 | 0.3965 | 0.5711 | 0.9989 | 候选几乎全召回，但内部排序明显不足 |
| NELL-v4 | 0.3199 | 0.5252 | 0.9789 | 候选召回很高，内部排序仍不足 |

## 2. 已失败或收益不足的改动

### 2.1 单纯增大PPR候选范围 / `topk=0.99`

做法：保留原来的固定PPR候选和传播框架，只显著增大候选集合。

结果：

- NELL-v1曾达到 `MRR=0.7289, H@10=0.8905`，说明增大候选范围对答案召回不足的数据可能有效。
- NELL-v2在相同方向下只有约 `MRR=0.3641, H@10=0.5251`；后续最好结果约为 `MRR=0.3965, H@10=0.5711`。
- NELL-v2的PPR答案召回已经达到 `0.9989~1.0000`，但H@10仍然较低。

结论：`topk=0.99` 不是三个数据集通用的解决方案。候选已召回时，继续扩大固定PPR集合会增加关系无关噪声，无法解决候选内部排序。

### 2.2 PPR外节点只作为progressive传播证据

做法：在固定PPR候选之外逐层加入证据节点，用局部attention/hard top-k控制扩展；最终排序仍主要依赖原候选或静态扩充后的候选集合。

代表结果（WN18RR-v1）：

- `MRR=0.7088, H@10=0.8137`
- `PPRGraphAnsRec=0.8646`
- `FinalCandidateAnsRec=0.8794`
- `FinalCandAvg=75.9`

与此前 `MRR=0.7153, H@10=0.8137` 相比，候选召回略有提高，但H@10没有提高，MRR反而下降。

结论：仅扩大证据或候选范围不够。旧progressive没有让查询关系决定完整的逐层传播路径，也没有形成连接保留的学习式采样，因此未解决内部排序问题。

### 2.3 让GNN先独立排名，再让FM学习残差

做法：增加GNN基础打分器和直接ranking监督；FM从GNN基础分数出发，只学习分数修正。

代表结果（WN18RR-v1）：

- 最终：`MRR=0.7178, H@10=0.8190`
- 基础GNN：`BASE_MRR=0.7188, BASE_H@10=0.8190`
- `FM_RANK_GAIN=-0.0010`
- `ZERO_Z_MRR=0.7187`
- `SHUFFLED_Z_MRR=0.7192`

结论：最终结果几乎完全由基础GNN决定，VAE/FM没有提供正增益。这一改法破坏了“潜变量条件化的独立score flow”这一核心贡献，但没有带来足够指标提升，已放弃。

### 2.4 BASE/DEEP辅助监督、FM gate与双分支融合

做法：加入基础排名、深层辅助排名、FM门控或双分支融合，希望先强化GNN，再由FM补充。

训练中曾出现：

- `BASE` 与最终ranking几乎相同。
- `FMGATE` 很小，FM对输出贡献接近零。
- `FM_RANK_GAIN` 接近零或为负。

结论：增加更多中间监督和融合门不能自动提高路径推理能力，反而容易让优化绕过VAE/FM，由GNN基础分支直接完成任务。

### 2.5 分阶段训练：先GNN、再VAE/FM、最后联合微调

做法：前期只训练GNN，中期冻结GNN训练VAE/FM，后期联合微调。

代表结果（WN18RR-v1）：

- `MRR=0.6949, H@10=0.7949`
- `GNN_MRR=0.6964, GNN_H@10=0.8016`
- `FM_MRR=0.6472, FM_H@10=0.6917`
- `FM_RANK_GAIN=-0.0015`

结论：分阶段训练没有解决主干证据质量问题，且FM分支明显弱于GNN。训练日程不是当前主要瓶颈。

### 2.6 PPR结构特征 / multiscale结构输入

做法：向候选表示或潜变量输入加入PPR、层级或多尺度结构特征，希望替代inductive中不可使用的实体ID表示。

代表结果（NELL-v2）：

- epoch 5：`MRR=0.3735, H@10=0.5540, XMOVE=14.8359`
- epoch 6：`MRR=0.3965, H@10=0.5711, XMOVE=1.8790`
- `PPRGraphAnsRec=0.9989`

结论：结构特征带来有限波动，但没有接近 `H@10=0.646~0.660` 的对比水平；早期还出现过不稳定的score movement。静态结构特征不能替代查询相关的传播路径选择。

### 2.7 仅降低VAE重构误差

现象：VAE重构MSE曾从约 `0.07~0.08` 降到 `0.007~0.008`，但WN18RR指标只从约 `MRR=0.7126, H@10=0.8043` 变化到 `MRR=0.7153, H@10=0.8137`。

结论：重构更准确不等于候选排序更准确。VAE重构误差不是当前主要瓶颈。

### 2.8 单纯增加候选召回

NELL-v2和NELL-v4已经分别达到约 `0.999` 和 `0.979` 的PPR答案召回，但H@10仍只有约 `0.571` 和 `0.525`。

结论：候选召回高只是必要条件，不是充分条件。主要问题已经从“答案是否进入候选”转为“关系相关证据能否把答案排入前10”。

### 2.9 查询感知的连接保留增量传播（联合实验）

做法：

1. PPR以 `ppr_pool_topk=0.99` 生成宽搜索池。
2. 每层只从已保留节点继续传播。
3. 新frontier按候选状态、查询关系和PPR软先验共同打分。
4. 历史选中节点始终保留，最后一层frontier进入最终候选。
5. 节点改为GRU式更新，并对各层状态做查询自适应融合。
6. VAE、FM起点、FM目标和五项损失保持不变。
7. checkpoint统一按验证集H@10选择，并用同一checkpoint报告全部指标。

最终结果：

- VALID：`MRR=0.3667, H@1=0.2998, H@3=0.3943, H@10=0.4939`
- VALID：`PPRGraphAnsRec=1.0000, FinalCandidateAnsRec=0.9207`
- VALID：`FinalCandAvg=725.7, FinalCandP95=1128.4`
- TEST：`MRR=0.3058, H@1=0.2470, H@3=0.3358, H@10=0.3990`
- TEST：`PPRGraphAnsRec=0.9964, FinalCandidateAnsRec=0.7251`
- TEST：`FinalCandAvg=150.1, FinalCandP95=431.0`

中途checkpoint的TEST结果：

- `MRR=0.2769, H@1=0.1800, H@3=0.3418, H@10=0.4513`
- `PPRGraphAnsRec=0.9964, FinalCandidateAnsRec=0.7251`
- `FinalCandAvg=150.1, FinalCandP95=431.0`

失败原因：

- 测试集PPR搜索池召回为 `0.9964`，但硬采样后的最终候选召回只有 `0.7251`，约27.1%的正确答案在进入VAE/FM之前被剪掉。
- 验证集与测试集的最终候选平均规模分别为 `725.7` 和 `150.1`，相差约4.8倍；最终候选召回也从 `0.9207` 降至 `0.7251`。这说明学习到的硬传播路径没有稳定迁移到不可见实体图。
- 中途到最终checkpoint期间，MRR和H@1提高，但H@10从 `0.4513` 降至 `0.3990`，说明模型进一步集中于少量头部候选，而不是VAE/FM整体崩溃。
- `PPRGraphAnsRec` 接近1，因此失败点不是宽PPR搜索池，而是查询感知硬采样和最终候选裁剪。

结论：本次联合方案整体判定失败，查询感知硬采样与最终候选裁剪不再继续。由于GRU、多层融合和硬采样同时启用，本次结果只能直接否定联合方案及硬裁剪，不能单独证明GRU或多层融合无效。代码已由用户回退。

## 3. 尚不能判定失败的改动

### 3.1 多正例逐一对比损失 + Hard-negative课程

当前待验证版本不再用 `logsumexp` 将同一query的全部正确答案合并成一个正例，而是要求每个正确答案分别超过所选负例。所有inductive数据集默认训练50轮，负样本总量固定为64个：第1～10轮全部随机采样，第11～25轮将hard比例从0线性增加到50%，第26～50轮保持32个hard与32个随机。用户显式指定 `--epochs` 时仍按20%/30%/50%的比例自动换算。PPR、候选集合、GNN、VAE/FM和checkpoint选择均保持回退基线不变，run tag会记录实际轮数，例如默认50轮为 `_multipos_negcurr_e50`。该改动尚无正式指标，因此暂不写成有效或失败结论。

## 4. 后续实验判定标准

- 必须与回退后的统一基线使用相同数据、seed、训练轮数和评估协议。
- 同时观察 `PPRGraphAnsRec` 与 `FinalCandidateAnsRec`：前者衡量搜索池召回，后者衡量查询感知传播后的最终召回。
- 如果 `FinalCandidateAnsRec` 大幅下降，则是采样过强；如果召回保持但H@10不升，则说明传播状态或最终排序仍有问题。
- 不能用 `H@10@50` 代替全实体 `H@10`。
- 正式对比必须使用同一个验证集选出的checkpoint报告MRR、H@1、H@3和H@10。
